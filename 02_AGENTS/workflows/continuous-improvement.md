# Workflow: mejora continua

## Objetivo

Hacer que MyRoom mejore con cada uso, incluso cuando distintos chats o agentes trabajen en momentos separados.

## Cuando usarlo

Al cierre de toda tarea, antes de marcarla como `done`, `blocked`, `waiting_approval` o `archived`.

## Revision de aprendizaje

Preguntar:

1. Aprendimos una preferencia estable del usuario?
2. Aprendimos un dato no sensible que futuros agentes necesitaran?
3. Descubrimos un mejor workflow, plantilla, regla o fuente?
4. Aparecio un error, bloqueo o decision que conviene evitar repetir?
5. Hay un proyecto, tramite, curso, automatizacion o repo que debe quedar actualizado?

## Donde registrar

| Tipo de aprendizaje | Archivo |
| --- | --- |
| Preferencias del usuario, estilo, criterios generales | `08_RESOURCES/knowledge/user-operating-profile.md` |
| Procedimiento reusable | `02_AGENTS/workflows/` o `08_RESOURCES/knowledge/` |
| Plantilla reusable | `08_RESOURCES/templates/` |
| Estado o decision de tarea | `02_AGENTS/tasks/YYYY-MM-DD-slug/record.md` |
| Proyecto personal | `03_PROJECTS/` |
| Universidad o estudio | `04_UNIVERSITY/` o `05_STUDY/` |
| Tramite | `07_TRAMITES/` |
| Automatizacion | `06_AUTOMATIONS/` |
| Proyecto externo o repo | `12_PROJECT_NETWORK/` |
| Accion externa o secretariado | `10_SECRETARIAT/` |

## Reglas

- Registrar lo suficiente para que otro agente pueda continuar sin redescubrir.
- Mantener los datos sensibles fuera de Git o referenciados sin valores completos.
- No inflar los archivos con observaciones triviales; registrar informacion estable, accionable o reutilizable.
- Si se actualiza una regla de operacion, enlazarla desde `AGENTS.md`, `README.md` o `01_DASHBOARD/operating-system.md` cuando todos los agentes deban verla.

## Cierre

Antes de cerrar, el `record.md` de la tarea debe decir:

- que se aprendio
- donde se registro
- que queda pendiente para mejorar el sistema
